01Overview

Linkdexing is a backlink indexing service for SEO professionals and agencies. Customers create an account, buy credits and submit links for indexing — in bulk, spread out over time, or as re-index requests for pages that have dropped out of Google's index.

The indexing itself is carried out by the Linkdexing team. The software runs everything around that work: accounts, credits, submissions, processing and administration.

02The problem

SEO teams submit links in large batches and want to pay for what they use rather than a monthly subscription. The business needs to sell credits, accept bulk and scheduled submissions reliably, keep customer accounts secure, and give its own team the tools to manage users and orders.

03The solution

A SaaS platform split into three applications that share one API: a customer-facing frontend, a backend that owns the business logic and data, and a separate admin application for the Linkdexing team.

04My contribution

I built all three applications — frontend, backend and admin — including:

  • REST API in Node.js and Express, with MongoDB and Mongoose.
  • Authentication with JWT, hashed passwords (Argon2 / bcrypt), OTP verification and transactional email.
  • Credits and bulk operations — purchasing, balances and bulk link submissions.
  • Security middleware including Helmet and rate limiting.
  • Admin application for user management and administration.

05Key features

Credit-based billing

One credit per link, sold in packages. No subscription, and credits don't expire.

Bulk submissions

Large batches of URLs submitted in one go.

Drip-feed scheduling

Spread a submission over anything from one to 30 days.

Re-indexing

Resubmit links and pages that have dropped out of the index.

Secure accounts

Registration with OTP verification, JWT sessions and hashed passwords.

Admin application

A separate app for the Linkdexing team to manage users and administration.

09Engineering decisions

  • Separate admin application. Internal tooling lives apart from the customer app, so admin features never ship to customers' browsers.
  • Security as a baseline. Modern password hashing, security headers and rate limiting on the API from the start.
  • One API, several clients. Business logic stays in the backend, so the frontend and admin app stay thin.
